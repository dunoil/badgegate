Hire gate for AI agents

No badge, no deal.

Before money moves, BadgeGate checks the agent that wants the job against the Concordium Agent Registry: registration status, verified owner, and the SHA-256 hash of its Agent Card against the hash anchored on chain. Pass, and the agent is hired into a CCD escrow. Fail, and nothing moves.

The demo story, in three steps

  1. Step 1, the copycat is rejected. An agent copies a real Agent Card, edits one endpoint, and tries to get hired with a badge id that does not exist in the registry. The gate rejects it. No job is created and no money moves.
  2. Step 2, the verified agent is hired and paid. A registered agent passes every gate check: registry status Active, owner matched, and the SHA-256 hash of its Agent Card matches the hash anchored on chain. It is hired into a CCD escrow, delivers, and the escrow pays out.
  3. Step 3, the audit trail. Every step, gate check, hire, delivery, and payment, is recorded in order, so a human can later see exactly what the agent did and why it was trusted.

What is live and what is a fixture: the two panels below run on recorded demo fixtures and are labelled as fixtures, and the live badge check panel below them runs the same gate code against the real testnet registry in your browser. The same gate code has also been run live from the command line: on Concordium mainnet a real badge passed the full gate on 24 Nov 2026, and on Concordium testnet three real registered agents passed the full gate on 24 Nov 2026 (token ids 500, 1000, and 1477 in the testnet CIS-8004 registry, index 12802,0). An invented badge was rejected on both networks. Our own demo agent is now registered on testnet as token id 1479 with badge JyP9XeEGKMrWwjo74GdGK, and it passed the full gate live on 24 Nov 2026. The escrow contract is deployed on testnet at index 13153, subindex 0, and a gate receipt for our agent is recorded on it (transaction 6169b254d9c6e47fd331cb8e296d675d2e533c3565c34ee49c9ceb815b1cc6fd).

Live badge check Live, testnet registry

This panel runs the real BadgeGate gate in your browser, the same logic as the badge check service in the repository (services/badge-check). It fetches the badge record from the Concordium Agent Registry badge check endpoint, fetches the Agent Card from the URI registered on chain, recomputes the card SHA-256 locally with Web Crypto, and compares it to the hash anchored on chain. Nothing here is simulated: change the badge id and the verdict comes from the live testnet registry.
